# SystemExplorer bounded threat model

## Scope, assets and trust boundaries

Source/configuration review at `0a4975a4763ad202747397ef5daf5893849b5b00`, 2026-11-05. No exploit testing, dependency advisory scan, binary linkage audit or comprehensive kernel audit was performed. This document records observed evidence and proposed controls; it does not certify absence of vulnerabilities.

**New application target:** a local, standard-user Windows 11 x64 monitor, with no automatic cloud integration and no required driver. Architecture is still subject to parent approval. **Preserved upstream:** System Informer contains powerful process actions, plugins, network features and optional kernel integration; their presence is not a commitment to expose them in the new UI.

Assets: correct process-instance identity and attribution, machine availability, privileged handles, personal process paths/command lines/usernames/network endpoints, local settings/logs, signing credentials, and trustworthy release binaries/notices. Treat observed process metadata as untrusted text, including filenames, publisher strings, command lines and icon/image resources.

Boundaries: Windows process APIs -> provider -> immutable snapshot/ABI -> UI; unprivileged UI -> any future elevated broker/driver; local configuration/plugins/files -> executable code; build inputs -> packaged artifacts; local process information -> any export or network destination. An administrator/kernel attacker already controlling the host is outside the protection guarantee; ordinary access denial must still be handled safely.

## Threats and required controls

| Threat | Evidence / current boundary | Required new-app mitigation and verification |
| --- | --- | --- |
| PID reuse / delayed result misattribution | `SystemInformer/procprv.c` compares sequence numbers or creation times in provider refresh and record lookup. | Instance key must survive sort/filter and reject stale asynchronous results. Parent PID, executable name and PID alone are not authority. Test same PID/new creation identity and exited selection (QUALITY_GATES M1). |
| Permission escalation or unsafe action | `KSystemInformer/README.md` describes verified caller, signing/privilege/state restrictions and restrictions on unsigned plugins. It also documents development policy bypasses. | Do not follow bypass instructions. Driverless read-only baseline; least query rights; explicit unavailable fields. Do not expose suspend/end-task merely because the reference image shows them. Any later destructive action requires separate approval, explicit target identity validation using the opened handle, confirmation and protected-target policy. No destructive testing now. |
| Untrusted metadata crosses ABI/UI | Existing native providers are not automatically a standalone SDK; process exit invalidates assumptions across refresh. | Version/size/ownership contract, bounded strings/arrays, copied immutable snapshots, cancellation and generation checks. No raw native pointers retained by UI. Display strings literally; no shell-command interpolation or executing an inspected path. For file-location navigation, handle absent/denied paths and avoid unintended UNC/network access. |
| Sensitive information leaves machine | `plugins/OnlineChecks/main.c` has VirusTotal lookup and explicit file/service upload handlers for several services. Presence is verified; default unsolicited transmission was **not** established. | New app must not automatically load upstream online plugins or reuse stored consent/keys. No online lookup/upload/update integration without explicit approval. Logs/exports exclude command lines and full usernames/paths by default; redact screenshots before sharing. Test fresh settings and inherited-settings migration separately. Preserve upstream behavior rather than silently rewriting it in this task. |
| UI or host denial of service | Process churn and slow/denied queries are normal; no runtime stress result was collected. | Bound concurrent queries, queues, history and metadata caches; coalesce refreshes; never block UI on slow path/icon/signer lookups. Test bounded children and cancellation; do not spawn an unbounded process storm. Unsupported/per-process failures must not cancel the whole snapshot. |
| Misleading measurements drive unsafe recommendations | `procprv.c` keeps `WorkingSetPrivateSize`, `VmCounters` and `PagefileUsage` history separately. | Specify units/provenance/availability/time. No shared-WS sum labeled total physical RAM, no commit called resident memory, no zero substituted for access denied. No recommendation to disable security/essential services based merely on memory usage. |
| Plugin/DLL or packaged-input trust | Upstream driver protects client image integrity; existing plugin functionality is broader than new-app scope. | Prefer no automatic native plugin loading in the new app. Define trusted runtime/dependency paths and no loading from arbitrary working directories; validate on fresh extraction. Retain upstream driver protections, do not copy private signing material into packages. Test actual packaged dependencies, not only source configuration. |
| Build/release supply chain | Workflow actions are SHA-pinned; builds restore explicit SDK/WDK package versions. Caches and floating runner labels remain inputs; CodeQL driver pack is not fully pinned. | Record toolchain/package identities and hashes, clean-build evidence and artifact inventory. Separate untrusted PR build permissions from signing/release credentials. No publish/upload action in baseline QA. Signing and public distribution remain approval-gated. |

## Actionable preexisting posture gaps

These are configuration/source observations, **not confirmed exploitable vulnerabilities**.

1. **Tests are not a current CI gate.** No phlib-test/ctest/vstest/dotnet-test invocation was found in `.github/workflows/` and the top-level solutions/CMake entry points. `tools/tests/phlib-test/main.c` calls four utility suites; their `assert` checks coexist with Release `NDEBUG` in `phlib-test.vcxproj`. Recommendation: build/run Debug tests and add explicit new-provider contract tests with failure-producing assertions. Keep tests separate from build success. Owner: build + QA, before M1 acceptance.
2. **Existing static analysis is scheduled/manual.** `.github/workflows/scan.yml` has no PR trigger and downloads `microsoft/windows-drivers` without an explicit version. Recommendation: decide PR coverage and pin query-pack provenance; do not describe the present setup as a per-PR security guarantee. Actual Actions run results/branch protections were not inspected. Owner: build/release.
3. **Fork governance still routes upstream.** `SECURITY.md` directs reports to System Informer; `.github/workflows/cla.yml` uses `pull_request_target`, elevated token permissions and an upstream Winsider CLA repository/document. No checkout/execution of PR source appears in that CLA job, so no PR-code-execution vulnerability is alleged. Recommendation: parent choose fork disclosure/CLA policy, minimize permissions and preserve upstream notices; do not silently reuse upstream response promises. Owner: parent, before public launch.
4. **License summary is not an artifact inventory.** Root MIT license does not override component licenses; root notices disagree with current vendored source in places (below). Recommendation: resolve provenance and shipped linkage before public release, not a blanket rewrite of original licenses. Owner: release + parent/legal review.
5. **Cloud functionality already exists upstream.** OnlineChecks handlers and CustomBuildTool commands (`-vtscan`, `-pipeline-deploy`, `-github-create-release`) demonstrate external capabilities. Recommendation: keep these outside new-app acceptance and avoid invoking them in testing. No claim of covert telemetry or automatic upload is made. Owner: frontend/provider + release.

### Closure evidence required

For each actual delivered artifact: component name/version or source hash, upstream source, applicable license/notice path, modified status, runtime vs build/test-only classification, proof of inclusion (project and linker map/object evidence), redistribution obligations and reviewer disposition. Include package transitive dependencies and native DLL/runtime dependencies. Preserve MIT attribution and ship the applicable third-party notices. Escalate ambiguous/copyleft obligations for explicit review; do not delete/relicense original source to conceal uncertainty.

## Acceptance and residual risk

Use [QUALITY_GATES.md](QUALITY_GATES.md) for identity, denial, churn, memory, native GUI, performance and release checks. The new app must pass standard-user/no-driver behavior with no automatic network integration. Native ABI safety, actual binary dependencies, plugin isolation, signature status and no-network behavior remain **unverified until implementation/artifacts exist**. A no-network claim needs provider/startup-path review and local observation of the tested flows; a snapshot of TCP endpoints alone cannot prove absence of transient traffic. Public distribution remains blocked on artifact-specific licensing/provenance and independent acceptance, not on the mere existence of this document.
