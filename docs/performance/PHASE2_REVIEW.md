# Phase 2 performance and package review

## Checkpoint and decision

This is an evidence-backed **investigation**, not an optimization result. Production source reviewed: [`9101b5580d10531f49ec566e0837c7f28339a3dd`](https://github.com/EgerDev/SystemExplorer/commit/9101b5580d10531f49ec566e0837c7f28339a3dd). Only this report is owned/changed. No application, provider, build-script, sampler, lockfile, upstream-notice or frontend changes are authorized at this checkpoint.

**Recommend one isolated, reversible experiment after parent approval:** replace the direct `Microsoft.WindowsAppSDK` **2.6.5** metapackage reference with `Microsoft.WindowsAppSDK.WinUI` **2.6.5**, regenerate the app lockfile, and retain the existing self-contained/unpackaged configuration and PRI publishing target. Do **not** add `Microsoft.WindowsAppSDK.Runtime`: it is the framework-deployment selector, unnecessary here; historical Microsoft guidance warns of aggregate payload when retaining it. Exact 2.6.5 self-contained targets now enumerate component packages, so do not assume every older extraction behavior still applies. Do not combine this with symbols, trimming, AOT, row-refresh or icon changes.

This is a supported package-selection mechanism, not proof that the candidate builds/runs correctly in this application, saves a particular number of bytes, or changes CPU/private commit. Parent must approve the hypothesis, own before/after and soak recipe/thresholds, review integration and give final visual acceptance. Proposed future ownership is limited to `ProcessIcons.cs`, `NativeTray.cs`, app csproj/lockfile and publish script; changes to `MainWindow`, `ShellViewModel`, Core or diagnostic providers require their owners' agreement.

### Exact pinned target evidence

`pinned-package-source.txt` preserves restored 2.6.5 NuSpec/props/targets text (not latest-main assumptions):

- Base `Microsoft.WindowsAppSDK.Base.targets` defaults component consumers to self-contained when no Runtime selector is present; imports SelfContained targets when true; enforces Runtime only for framework-dependent deployment. Existing explicit self-contained flags remain.
- Base `Microsoft.WindowsAppSDK.SelfContained.targets` enumerates `WindowsAppSdkComponentPackages` for native DLLs, PRI, metadata, MUI, XAML/XBF and package fragments; generates the activation manifest from those fragments. This explains why DLL deletion alone can leave stale registration/resource state.
- Runtime props sets `MicrosoftWindowsAppSDKPackageDir`; its targets condition framework imports on `WindowsAppSDKFrameworkPackageReference`, which self-contained targets disable. Do not port 1.8 Runtime extraction claims unqualified to 2.6.5.
- ML 2.6.5 targets explicitly document that managed self-contained native assets copy through normal NuGet RID resolution from MachineLearning `runtimes/`; framework/passthrough suppression does not suppress self-contained mode. `onnxruntime.dll` and `DirectML.dll` exact hashes match that 2.4.89 package.
- WinUI 2.6.5 nuspec matches the lockfile dependencies: Base, Foundation, InteractiveExperiences and WebView2. It does not declare AI, ML, Search, Widgets or DWrite. Exact graph/candidate runtime checks are still required before accepting an omission.
