## Async UI operation contract

New async UI operations use `SystemExplorer.Core.OperationGate`, on the UI thread only. `TryBegin` changes Idle to Running and returns a ticket with a strictly increasing generation and a linked CancellationToken. A busy gate refuses another begin. `RequestCancel` changes Running to Cancelling and signals the token; it does not release ownership. `Complete(ticket)` changes Running/Cancelling to Idle only for the current ticket and returns whether completion may publish. Double completion, stale/foreign tickets, double begin and cancellation while idle are no-ops. Always complete in finally, and never derive busy state from a Task/provider/CTS presence. Use `IsCurrent` for intermediate progress and a selection/result version when publication also depends on view context. Cancellation requested through a linked lifetime token is observable through the ticket token; UI phase is not automatically changed by a worker-thread callback.

The gate models ownership, not success/failure or result availability. Keep `TraceStatus`, `StorageScanState`, `InspectionStatus`, `RamReadingStatus`, `CounterValueState`, `InventoryPhase` and result records as their existing outcome types. Operation kind identifies the active UI flow without multiplying phase booleans. A stopped Trace capture keeps the recorder's existing Completed/Partial/etc. semantics, even though its UI gate passes through Cancelling.

Hidden shares a gate across scan/export and additionally checks SelectionVersion for export status. RAM shares a gate across initialization, captures and export. Storage separates inventory loading (`StorageInventoryPhase` plus inventory gate) from scan/export (one work gate). Trace retains independent capture/export gates with mutual exclusion; query/summary generation logic remains separate.

## Verification and extension

Core.Tests is a console contract test runner: `dotnet run --project tests/SystemExplorer.Core.Tests -c Release`. OperationGateTests covers normal/empty/error completion, busy reentry, cancellation, linked lifetime cancellation, monotonically increasing generations, foreign/stale/double completion, and stale-selection publication. Its linked App presentation helper also checks terminal scan wording and truthful retained-observation cancellation text. Native smoke projects and portable publishing remain defined in `.github/workflows/systemexplorer.yml`; they do not substitute for visual state-transition testing.
